# وجبة — Data Model (MVP)

الملف ده بيوصف البيانات اللي هتتخزن في النسخة الأولى.  
الهدف: أبسط نموذج ممكن يخدم الـ Core Features من غير تعقيد.

---

## 1. الكيانات الرئيسية (Entities)

في الـ MVP عندنا كيانين أساسيين بس:

1. **User** (صاحب الوجبة / المستخدم)
2. **Meal** (الوجبة)

مفيش:
- Orders
- Reviews
- Messages
- Favorites (لسه)
- Notifications (مؤجلة)

---

## 2. User

يمثل أي شخص بيستخدم التطبيق (سواء ناشر أو مستكشف).

### الحقول

| الحقل              | النوع          | مطلوب؟ | ملاحظات                                      |
|--------------------|----------------|--------|-----------------------------------------------|
| `id`               | UUID / String  | نعم    | المعرف الفريد                                 |
| `name`             | String         | نعم    | الاسم الظاهر                                  |
| `whatsapp`         | String         | نعم    | رقم الواتساب (مثال: 01XXXXXXXXX)             |
| `area`             | String         | نعم    | المنطقة التقريبية (مثال: السيدة زينب)        |
| `avatar_url`       | String         | لا     | رابط الصورة (لو مفيش → Avatar تلقائي)        |
| `facebook_url`     | String         | لا     | رابط فيسبوك                                   |
| `instagram_url`    | String         | لا     | رابط إنستجرام                                 |
| `tiktok_url`       | String         | لا     | رابط تيك توك                                  |
| `created_at`       | DateTime       | نعم    | تاريخ إنشاء الحساب                            |
| `updated_at`       | DateTime       | نعم    | آخر تحديث                                     |

### ملاحظات مهمة
- مفيش كلمة مرور أو تسجيل دخول تقليدي في الـ MVP.
- البيانات دي بتتطلب أول مرة المستخدم يحاول ينشر وجبة.
- الـ `area` دايمًا تقريبية (مفيش عنوان دقيق).

---

## 3. Meal

يمثل الوجبة المنزلية اللي بيتنشر.

### الحقول

| الحقل                  | النوع              | مطلوب؟ | ملاحظات                                              |
|------------------------|--------------------|--------|------------------------------------------------------|
| `id`                   | UUID / String      | نعم    | المعرف الفريد                                        |
| `user_id`              | UUID / String      | نعم    | صاحب الوجبة (Foreign Key → User)                     |
| `title`                | String             | نعم    | اسم الوجبة (مثال: محشي بيتي)                         |
| `description`          | String             | لا     | تفاصيل الوجبة                                        |
| `price`                | Number             | لا     | السعر بالجنيه (اختياري)                              |
| `quantity`             | Number             | لا     | عدد الوجبات المتاحة                                  |
| `status`               | Enum               | نعم    | `available` أو `unavailable`                         |
| `images`               | Array of Strings   | نعم*   | قائمة روابط الصور (أول صورة = الرئيسية)             |
| `area`                 | String             | نعم    | المنطقة التقريبية للوجبة                            |
| `delivery_option`      | Enum               | لا     | `pickup_only` أو `delivery_available`                |
| `available_time`       | String             | لا     | وقت/يوم التوفر (نص حر حاليًا)                        |
| `show_location`        | Boolean            | نعم    | هل تظهر المنطقة للعامة؟ (افتراضي: true)             |
| `created_at`           | DateTime           | نعم    | تاريخ النشر                                          |
| `updated_at`           | DateTime           | نعم    | آخر تعديل                                            |

\* على الأقل صورة واحدة مطلوبة في معظم الحالات، لكن ممكن نسمح بنشر من غير صورة في المستقبل لو حابين.

### ملاحظات على الحقول
- **`status`**:  
  - `available` → تظهر في Home والبحث  
  - `unavailable` → تظهر فقط في «وجباتي» بشكل خفيف، ومش بتظهر في الاستكشاف أو البحث
- **`images`**: مصفوفة. العنصر الأول هو الـ Cover Image.
- **`show_location`**: حتى لو true، المنطقة بتبقى تقريبية مش عنوان دقيق.
- مفيش حقل لإخفاء رقم الواتساب (الرقم دايمًا متاح لأنه طريقة التواصل الوحيدة).

---

## 4. العلاقات (Relationships)

```
User 1 ─────── * Meal
```

- كل User يقدر ينشر أكتر من Meal.
- كل Meal ليها صاحب واحد بس (`user_id`).

---

## 5. ما لا يتم تخزينه في الـ MVP

- أي بيانات طلبات أو مدفوعات
- رسائل أو محادثات
- تقييمات أو تعليقات
- قائمة المفضلة (Favorites)
- سجل الإشعارات
- موقع GPS الخام (نحتفظ بالمنطقة التقريبية فقط)
- أي بيانات تتبع معقدة

---

## 6. ملاحظات تقنية سريعة

- يُفضل استخدام UUID للمعرفات.
- الصور تتخزن على Storage (Firebase Storage / S3 / مشابه) ونحفظ الروابط فقط.
- البحث هيشتغل على: `title` + `description` + `area` + `User.name`
- الوجبات اللي `status = unavailable` تتجاهل في استعلامات الـ Home والبحث.

---

## 7. ملخص سريع

| الكيان   | الغرض الرئيسي                     | أهم الحقول                          |
|----------|-----------------------------------|-------------------------------------|
| User     | بيانات الشخص اللي بينشر أو يتواصل | name, whatsapp, area, social links |
| Meal     | الوجبة نفسها                      | title, images, status, price, area |
